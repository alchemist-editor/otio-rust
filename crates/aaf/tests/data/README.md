# Test fixtures

Two AAF files, and a manifest of what upstream reads out of each.

| File | Version | Sector size | Entries |
|---|---|---|---|
| `empty.aaf` | 4 | 4096 | 766 |
| `sector_size_512.aaf` | 3 | 512 | 1386 |

Between them they cover both sector sizes the format allows, along with mini
streams, multi-sector directories and a DIFAT that outgrows the header.

## Provenance

Both files come from [`pyaaf2`][pyaaf2]'s own test suite, at revision
`08dcc3dfe823ea5781db1cb657d9c2606557fcdc`, and are used here under that
project's MIT licence. `empty.aaf` is a minimal AAF written by pyaaf2 itself;
`sector_size_512.aaf` is a 512-byte-sector file as older applications write
them.

`test_file_01.aaf`, the third file in that suite, is deliberately not vendored:
it is 2.3 MB, and the coverage it would add over these two is a stream large
enough to bypass the mini stream. The root storage's own stream serves for
that, and `mini_streams_are_slices_of_the_root_stream` uses it.

## The manifests

`*.manifest.tsv` lists every directory entry in the matching file — its path,
kind, class AUID, and for streams the length and a SHA-256 prefix of the
contents — as read by pyaaf2. They were generated by opening each file with
`aaf2.cfb.CompoundFileBinary` and walking it, so a test that matches one is
checking this port against the library it is a port of, not against its own
earlier output.

Regenerate them only against a pyaaf2 checkout, never from this crate's own
reader: a manifest produced here would agree with any bug it has.

[pyaaf2]: https://github.com/markreidvfx/pyaaf2

`*.objects.tsv` is the same idea one layer up: every AAF object reached by
walking the strong references from the root, with its class and the full list
of properties it holds, as read by pyaaf2. A property's value is recorded in
whatever form its storage format gives — a name for a reference, a key for a
weak reference, a count for a collection, a length and content hash for inline
data. `*.values.tsv` is the layer above that: the same inline data decoded
against the type each property declares.

`*.metadict.tsv` lists every class and type each file *stores* in its meta
dictionary — not pyaaf2's built-in tables merged with them, which is a larger
set. For classes it records the name, parent, concreteness and every property
the class declares; for types, the category and whatever that category needs.

`*.values.tsv` records every data property of every object, decoded by pyaaf2
with the type the file says it has: the owning storage, the property's pid, the
type's name and the value. Where pyaaf2 packages a decoded record into a Python
object — `TimeStruct`, `DateStruct` and `TimeStamp` into `datetime`, `Rational`
into `Fraction` — the manifest records the members instead, because that
packaging sits on top of the decode and this crate hands back the members. Each
member is still decoded by pyaaf2. `AUID` and `MobID` are decoded whole, as
both sides do.

Fifty rows of `sector_size_512.values.tsv` are counted rather than compared,
because the definitions they need are ones pyaaf2 has built in and the file does
not carry: 36 belong to classes the file's `ClassDefinitions` omits, and 14 to
`aafInt64Array`, a type it uses without defining. `matches_pyaaf2_on_every_decoded_value`
asserts that number, so porting the built-in definitions will take it to zero
rather than quietly changing what is covered.
